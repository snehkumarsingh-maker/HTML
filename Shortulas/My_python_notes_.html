I.1Python versions

Python exists in two major lineages: Python 2, which reached end-of-life on 1 January 2020, and Python 3, the version every current compiler, exam, and IDE uses. Always assume Python 3 unless a question says otherwise.

FeaturePython 2Python 3
printprint "hi" (statement)print("hi") (function)
Integer division5/2 → 25/2 → 2.5, use // for floor division
Inputraw_input()input()
StringsASCII by defaultUnicode by default
EXAM POINTERThis table is a favourite two-mark question: "Differentiate Python 2 and Python 3." Memorise at least the print statement and division rows.

I.2Python on Windows & running "Hello World"

Install Python from python.org, and on the first installer screen tick "Add python.exe to PATH" — this is the single most common setup mistake, and it's why python "is not recognised" in the command prompt afterwards. The installer bundles IDLE (Integrated Development and Learning Environment), a basic editor with a Python shell.

Python code runs in two modes:

  • Interactive mode — type directly at the >>> prompt; each line is evaluated immediately.
  • Script mode — write statements in a .py file and run it as python hello.py.
# hello.py — the traditional first program
print("Hello, World!")
WHY THIS MATTERS"Hello, World!" verifies three things at once: the interpreter is installed, PATH is correct, and you understand that print() is a function call in Python 3.

I.3Naming and using variables

A variable is a name that refers to a value. Assignment (=) creates or updates that reference — it does not create a labelled box holding a copy; it binds a name to an object already sitting in memory.

message = "What's up, Doc?"
n = 17
pi = 3.14159

A statement like this is called an assignment statement. It has a target on the left and an expression on the right; the expression is evaluated first, then bound to the name.

I.4Avoiding NameError

Using a variable before it has been assigned raises NameError: name 'x' is not defined. It is one of the most common runtime errors for beginners, usually caused by a typo, wrong case (Total ≠ total), or reading a variable before the line that creates it has executed.

print(count)   # NameError — count was never assigned
count = 0
print(count)   # fine now
COMMON TRAPPython is case-sensitive: Age, age, and AGE are three different variables. A stray capital letter is the #1 cause of "surprise" NameErrors in lab exams.

I.5Values and types

A value is a piece of data a program manipulates — 17, 3.14, "hello". Every value has a type, and type() reports it.

A numeric string like "17" is still a str, not an int — this distinction underlies many exam "spot the type" questions and every int()/float()/str() conversion.

I.6Variable names and keywords

A legal variable name starts with a letter or underscore, contains only letters, digits and underscores after that, and cannot be one of Python's 35 reserved keywords — words the language itself needs, so they can't double as identifiers.

I.7Statements

A statement is an instruction the interpreter executes — it produces an effect (bind a name, print something, import a module) rather than a value. A script is simply a sequence of statements executed top to bottom.

import math        # import statement
n = 5                # assignment statement
print(n)             # expression statement

I.8Operators and operands

An operator is a special symbol that performs computation (+ - * / // % **); the values it acts on are its operands. In 3 + 4, + is the operator, 3 and 4 are the operands.

OperatorMeaningExample
+ - *add, subtract, multiply7 * 3 → 21
/true (float) division7 / 2 → 3.5
//floor division7 // 2 → 3
%modulus (remainder)7 % 2 → 1
**exponent2 ** 5 → 32

I.9Order of operations

Python follows the same precedence rules as ordinary algebra, remembered by PEMDAS: Parentheses, Exponentiation, Multiplication/Division/Floor-division/Modulus (equal rank, left to right), then Addition/Subtraction. Exponentiation is the only operator that groups right to left.

print(2 + 3 * 4)     # 14 — multiplication first
print((2 + 3) * 4)   # 20 — parentheses override
print(2 ** 3 ** 2)    # 512 — right-associative: 3**2 first

I.10Operations on strings

Strings don't support - / %, but they overload two arithmetic operators with new meanings: + becomes concatenation and * becomes repetition (string × int only).

first = "tur"
second = "tle"
print(first + second)   # 'turtle'
print("Spam" * 3)     # 'SpamSpamSpam'
COMMON TRAP"3" + "4" gives "34" (concatenation), not 7. Mixing a string and an int with +, e.g. "age: " + 20, raises a TypeError — you must wrap the number in str() first.

I.11Composition

Composition is the ability to combine small expressions and statements into larger ones — a function call inside an arithmetic expression, an expression as an argument to another function call. It's what lets a handful of rules generate an unlimited variety of programs.

hour = 11
minute = 59
print("Number of minutes since midnight:", hour * 60 + minute)

I.12Comments

Anything after a # is ignored by the interpreter. Comments explain why code does something, for the benefit of humans — not what it does line by line.

# compute the percentage of the hour that has elapsed
percentage = (minute * 100) / 60

Unit I — last-night recap

  1. Python 3 uses print() as a function; / always returns a float.
  2. A variable is a name bound to a value, not a box holding one.
  3. NameError = used before assigned (often a typo or case mismatch).
  4. 35 keywords are off-limits as identifiers — know the list by shape, not by heart.
  5. PEMDAS governs precedence; ** is right-associative.
  6. + and * are overloaded for strings as concatenation/repetition.

II.1The modulus operator

% returns the remainder of integer division and is the workhorse of conditional logic: it tests even/odd, divisibility, and "wraps around" a range (clock arithmetic).

x = 7
print(x % 2)          # 1 → x is odd
print(15 % 5 == 0)  # True → 15 is divisible by 5

II.2Random numbers

The random module generates pseudo-random values — used for simulations, games, and testing.

CallReturns
random.random()float in [0.0, 1.0)

import random
dice = random.randint(1, 6)   # simulate one die roll, 1..6 inclusive
print(dice)

II.3Boolean expressions

A Boolean expression evaluates to exactly one of the two Boolean values True or False, produced by comparison operators: == != > < >= <=. Note == tests equality; = assigns — confusing them is a classic syntax error trigger.

print(5 == 5)   # True
print(5 == 6)   # False
print(5 != 6)   # True

II.4Logic operators

and, or, not combine or invert Boolean expressions. Python short-circuits: in a and b, if a is False, b is never evaluated.

II.5Conditional statements: if / if-else / if-elif

x = 5
if x % 2 == 0:
    print("x is even")
else:
    print("x is odd")

# chained conditional — checked top to bottom, first True wins
if x < 0:
    print("negative")
elif x == 0:
    print("zero")
else:
    print("positive")
EXAM POINTERIndentation is not style in Python — it is the block structure. An IndentationError is one of the most-lost marks in lab exams; be consistent (4 spaces is the convention).

II.6Nested conditionals

An if inside another if's body. Logically equivalent to combining conditions with and, but sometimes clearer — and sometimes less clear, since deep nesting gets hard to read. Prefer chained elif over deep nesting when the branches are mutually exclusive.

if x > 0:
    if x % 2 == 0:
        print("positive and even")
    else:
        print("positive and odd")

II.7The while statement

Repeats a block as long as a condition stays True; the condition is re-checked before every iteration, so the body can execute zero times. You are responsible for changing something so the loop eventually terminates.

n = 5
while n > 0:
    print(n)
    n = n - 1
print("Blastoff!")
COMMON TRAPForgetting to update the loop variable (n = n - 1) creates an infinite loop — one of the most common exam debugging questions asks you to spot exactly this.

II.8The for loop and range()

for iterates directly over a sequence's elements; when you need a counter, wrap it with range().

CallSequence produced
range(5)0, 1, 2, 3, 4
range(2, 7)2, 3, 4, 5, 6
range(0, 10, 2)0, 2, 4, 6, 8
for i in range(1, 6):
    print(i, "squared is", i ** 2)

for letter in "turtle":
    print(letter)

II.9Nested for and nested while

A loop inside a loop — the inner loop completes all its iterations for every single iteration of the outer one. Classic use: multiplication tables and pattern printing.

for i in range(1, 4):
    for j in range(1, 4):
        print(i * j, end=" ")
    print()   # newline after each row
# 1 2 3
# 2 4 6
# 3 6 9
WHY THIS MATTERSNested-loop pattern printing (stars, pyramids, number triangles) is one of the highest-frequency practical-exam question types — practise tracing the outer/inner index relationship, don't just memorise one pattern.

II.10Random numbers in loops

Combining random with iteration is how you simulate repeated trials — dice games, coin flips, Monte-Carlo style estimation.

import random
heads = 0
for toss in range(10):
    if random.randint(0, 1) == 1:
        heads = heads + 1
print("Heads came up", heads, "times out of 10")

II.11Encapsulation and generalization

These two words mean something specific and narrow here — don't confuse them with the OOP "data hiding" sense of encapsulation used in Unit V.

  • Encapsulation — wrapping a piece of working code inside a function so it gets a name, can be reused, and can be reasoned about as a single black box.
  • Generalization — replacing a hard-coded value inside that function with a parameter, so it now works for a whole class of inputs instead of one.
# before: hard-coded, one-off code
for i in range(1, 4):
    print(2 * i)

# after encapsulation: wrapped in a function
def print_multiples_of_2():
    for i in range(1, 4):
        print(2 * i)

# after generalization: n and high are now parameters
def print_multiples(n, high):
    for i in range(1, high + 1):
        print(n * i)

print_multiples(7, 5)   # now works for ANY table, not just the 2-times table
EXAM POINTER"Explain encapsulation and generalization with an example" is a direct theory question worth full marks for exactly the progression shown above — hard-coded → function → parameterised function.

Unit II — last-night recap

  1. % tests divisibility/parity; and/or/not combine conditions and short-circuit.
  2. if/elif/else checks top-down, first match wins; indentation defines the block.
  3. while checks its condition before every pass; you must update the loop variable yourself.
  4. for x in range(...) is the standard counting loop; for x in sequence iterates elements directly.
  5. Nested loops: inner loop finishes completely for each single step of the outer loop.
  6. Encapsulation = wrap in a function. Generalization = add a parameter.

Strings

III.1String as a compound data type

A string is a sequence — an ordered, indexed collection of characters. Being "compound" means you can pull it apart into smaller pieces using an index.

fruit = "banana"
print(fruit[0])    # 'b' — indexing starts at 0
print(fruit[-1])   # 'a' — negative index counts from the end

III.2Length

print(len("banana"))   # 6
COMMON TRAPThe last legal index of a string of length n is n - 1, not n. fruit[len(fruit)] raises an IndexError.

III.3String traversal

Visiting every character in order, typically with a for loop (Pythonic) or a while loop with an explicit index (useful when you need the position too).

for char in fruit:
    print(char)

# equivalent while-loop version
index = 0
while index < len(fruit):
    print(fruit[index])
    index = index + 1

III.4String slices

s[start:stop] extracts a substring — start is included, stop is excluded. Omitting either defaults to the beginning/end.

s = "Monty Python"
print(s[0:5])    # 'Monty'
print(s[6:])     # 'Python'
print(s[:5])     # 'Monty'
print(s[::-1])   # 'nohtyP ytnoM' — reversed, step = -1

III.5Comparison

Strings compare lexicographically using character ordinal values (like a dictionary, but case-sensitive — all capital letters sort before all lowercase letters in ASCII).

if "apple" < "banana":
    print("apple comes first")
print("Apple" == "apple")   # False — case-sensitive

III.6The find function

s.find(sub) returns the index of the first occurrence of sub, or -1 if it isn't present. in checks membership without giving a position; s.index(sub) is similar to find but raises ValueError instead of returning -1.

word = "banana"
print(word.find("na"))     # 2
print(word.find("z"))      # -1
print("na" in word)      # True

III.7Looping and counting

Traversal combined with a counter variable — the standard pattern for "count how many times X occurs."

def count_letter(word, letter):
    count = 0
    for char in word:
        if char == letter:
            count = count + 1
    return count

print(count_letter("banana", "a"))   # 3

Lists

III.8List values, length, membership

A list is an ordered, mutable collection, written with square brackets; it can mix types.

nums = [10, 20, 30]
mixed = [1, "two", 3.0, [4, 5]]
print(len(nums))        # 3
print(20 in nums)      # True

III.10Lists and for loops

for n in nums:
    print(n)

for i, n in enumerate(nums):    # when you need the index too
    print(i, "->", n)

III.11List parameters (aliasing) & nested lists

Lists are mutable and passed to functions by reference: the parameter name is just another alias for the same list object, so changes made inside the function are visible to the caller. A nested list is a list whose elements are themselves lists — the basis for matrices/2-D grids.

def clear_list(lst):
    lst[0] = 0          # mutates the SAME list the caller passed in

data = [1, 2, 3]
clear_list(data)
print(data)          # [0, 2, 3] — caller's list changed too!

matrix = [[1, 2, 3], [4, 5, 6]]   # nested list = 2x3 matrix
print(matrix[1][2])   # 6 — row 1, column 2
EXAM POINTER"Why does modifying a list inside a function change the caller's list?" is a guaranteed viva/theory question. The answer is aliasing: lists are mutable objects, and the parameter is just another name bound to the same object — this behaves differently from passing an int or str, which are immutable.

Tuples & Dictionaries

III.12Mutability and tuples

A tuple is a sequence like a list, but immutable — once created, it cannot be changed. Written with parentheses (or just commas); a single-element tuple needs a trailing comma or Python reads it as a plain value in parentheses.

t = (1, 2, 3)
single = (5,)     # the comma is required — (5) is just the int 5
# t[0] = 99   -> TypeError: 'tuple' object does not support item assignment

III.13Tuple assignment & tuples as return values

Tuple assignment unpacks multiple values in one line — most famously, the classic swap without a temporary variable. Functions also use tuples to return more than one value at once.

a, b = 1, 2
a, b = b, a          # swap — no temp variable needed
print(a, b)         # 2 1

def min_max(values):
    return min(values), max(values)   # packs two values into a tuple

lo, hi = min_max([4, 1, 9, 2])   # unpacks the returned tuple
print(lo, hi)      # 1 9

III.14Dictionary operations and methods

A dictionary maps keys to values — an unordered (in older Python, insertion-ordered since 3.7) collection accessed by key rather than position.

Method / operatorPurpose
d[key]access (raises KeyError if missing)
d.get(key, default)access safely, returns default if missing
d[key] = valueadd or update an entry
d.keys() / d.values() / d.items()views of keys / values / (key,value) pairs
d.pop(key)remove a key, return its value
key in dmembership test — checks keys, not values
ages = {"Riya": 21, "Sam": 19}
ages["Priya"] = 22              # add new key
print(ages.get("Zoe", 0))   # 0 — safe default instead of KeyError
for name, age in ages.items():
    print(name, "is", age)

III.15Sparse matrices

A sparse matrix is one where almost every entry is zero (or a default value). Storing it as a full nested list wastes memory; a dictionary keyed by (row, col) storing only the non-zero entries is far more efficient.

sparse = {(0, 2): 5, (3, 1): -2}   # everything else is implicitly 0

def get(matrix, row, col):
    return matrix.get((row, col), 0)   # default 0 for any un-stored cell

print(get(sparse, 0, 2))   # 5
print(get(sparse, 1, 1))   # 0

III.16Aliasing and copying

Two variables pointing at the same mutable object are aliases — changing one changes what the other sees, because there's only one object. A real copy is an independent object with the same contents.

a = [1, 2, 3]
b = a              # ALIAS — b and a refer to the same list
b.append(4)
print(a)           # [1, 2, 3, 4] — a changed too!

c = a[:]           # COPY — a new, independent list (slicing the whole thing)
c.append(99)
print(a)           # unaffected by changes to c

import copy
d = copy.deepcopy(a)   # independent copy, including nested lists inside
COMMON TRAPThis is the single most-tested "predict the output" question in Unit III. If you see b = a where a is a list, assume aliasing, not copying — int, float, str and tuple are immutable, so this trap never applies to them.

Unit III — last-night recap

  1. Strings and tuples are immutable sequences; lists and dicts are mutable.
  2. Slicing [start:stop:step] works identically on strings, lists, and tuples.
  3. find() returns -1 on failure; index() raises an error instead.
  4. Lists passed to functions are aliased, not copied — mutations inside are visible outside.
  5. Tuple unpacking swaps variables and lets functions return multiple values.
  6. b = a aliases a mutable object; use a[:], list(), or copy.deepcopy() for a real copy.

IV.1Function calls

A function call is an expression: name(arguments). Python ships many built-ins (len(), print(), type()) alongside whatever you define yourself.

result = max(3, 7, 2)   # 7 — calling a built-in function

IV.2Type conversion and coercion

Conversion is explicit: you call int(), float(), or str() yourself. Coercion is implicit: Python silently converts one operand's type to make an operator work, e.g. promoting an int to float in mixed arithmetic.

print(int("42"))     # 42 — explicit conversion
print(float(3))     # 3.0
print(3 + 4.0)      # 7.0 — 3 is silently coerced to float (implicit coercion)
# int("hello")  -> ValueError: invalid literal for int()

IV.3Math functions

import math
print(math.sqrt(16))    # 4.0
print(math.pi)          # 3.14159...
print(math.sin(0))      # 0.0
print(math.log(100, 10)) # 2.0 — log base 10

IV.4Adding new functions

A function definition begins with def, a name, parentheses holding zero or more parameters, and a colon; the indented body follows. A function that computes and hands back a value uses return (a fruitful function); one that just performs an action is a void function and implicitly returns None.

def greet(name):        # void function — no return value
    print("Hello,", name)

def square(n):          # fruitful function — returns a value
    return n * n

greet("Aarav")
result = square(5)     # 25

IV.5Parameters and arguments

Parameters are the names listed in the function definition; arguments are the actual values supplied at the call site. Python also supports default and keyword arguments.

def power(base, exponent=2):   # exponent has a default value
    return base ** exponent

print(power(5))               # 25 — uses default exponent
print(power(5, 3))            # 125 — positional argument
print(power(exponent=3, base=5))  # 125 — keyword arguments, order doesn't matter

A variable created inside a function has local scope — it exists only while that call is running, and is invisible outside it.

IV.6Recursion and its use

A recursive function calls itself, always with a smaller version of the problem, and must include a base case that stops the recursion — without one you get infinite recursion and a RecursionError. Each call is pushed onto the call stack; when the base case is reached, results unwind back up.

def factorial(n):
    if n == 0:            # base case — stops the recursion
        return 1
    else:
        return n * factorial(n - 1)   # recursive case — smaller problem

print(factorial(5))   # 5*4*3*2*1 = 120

def fib(n):
    if n <= 1:
        return n
    return fib(n - 1) + fib(n - 2)
TRACE ITfactorial(3) expands as 3 * factorial(2) → 3 * (2 * factorial(1)) → 3 * (2 * (1 * factorial(0))) → 3 * (2 * (1 * 1)) = 6. Being able to hand-trace this stack, line by line, is exactly what "dry run" questions test.
EXAM POINTER"Compare recursion and iteration" is a standard theory question. Recursion is often more readable for naturally self-similar problems (trees, factorial, Fibonacci) but costs more memory (one stack frame per call) and can hit Python's recursion limit; iteration is more memory-efficient but sometimes less natural to express.

Unit IV — last-night recap

  1. Fruitful functions return a value; void functions perform an action and return None.
  2. Conversion is explicit (int(), float()); coercion is implicit, done by the interpreter.
  3. Parameters live in the definition; arguments are supplied at the call.
  4. Every recursive function needs a base case, or it recurses forever.
  5. Practice hand-tracing recursive calls — it's the most common "predict the output" question type.

V.1Creating classes

A class is a blueprint for objects: it defines what data (attributes) and behaviour (methods) every object built from it will have. __init__ is the constructor, called automatically when an object is created; self refers to the specific object a method is operating on.

class Student:
    def __init__(self, name, marks):
        self.name = name      # instance attribute
        self.marks = marks

    def has_passed(self):
        return self.marks >= 40

V.2Creating instance objects

Calling the class like a function creates (instantiates) an object, running __init__ with the given arguments.

s1 = Student("Riya", 78)
s2 = Student("Sam", 33)

V.3Accessing attributes

Dot notation reads or sets an attribute; calling a method uses the same dot notation followed by parentheses. Python passes the object itself as self automatically — you never pass it explicitly at the call site.

print(s1.name)          # 'Riya'
print(s1.has_passed())  # True
s1.marks = 85            # attributes can be reassigned directly

V.4Class inheritance

A subclass (child) is written class Child(Parent): and automatically gets every attribute and method of the parent, plus whatever it adds — an "is-a" relationship. super().__init__(...) calls the parent's constructor to avoid repeating its setup logic.

class Person:
    def __init__(self, name):
        self.name = name

    def introduce(self):
        return f"I'm {self.name}"

class Student(Person):          # Student IS-A Person
    def __init__(self, name, roll_no):
        super().__init__(name)     # reuse the parent constructor
        self.roll_no = roll_no

s = Student("Sam", 21)
print(s.introduce())    # inherited method still works: "I'm Sam"

V.5Overriding methods

A subclass can redefine a method it inherits, replacing the parent's behaviour with its own — the same method name, called the same way, now does something different depending on the object's actual class. This is Python's route to polymorphism.

class Student(Person):
    def __init__(self, name, roll_no):
        super().__init__(name)
        self.roll_no = roll_no

    def introduce(self):             # OVERRIDES Person.introduce
        return f"I'm {self.name}, roll no {self.roll_no}"

print(Student("Sam", 21).introduce())
print(Person("Riya").introduce())

V.6Data hiding

Python has no true "private" keyword — its philosophy is "we're all consenting adults." Instead it uses naming conventions: a single leading underscore (_marks) signals "internal, please don't touch" by convention only; a double leading underscore (__marks) triggers name mangling, rewriting it internally to _ClassName__marks, which makes accidental external access harder (not impossible).

class Account:
    def __init__(self, balance):
        self.__balance = balance    # name-mangled -> _Account__balance

    def get_balance(self):           # controlled access via a method
        return self.__balance

a = Account(1000)
print(a.get_balance())   # 1000 — correct way in
# print(a.__balance)   -> AttributeError
print(a._Account__balance)  # 1000 — still reachable if you know the mangled name
EXAM POINTERA frequent trick question: "Is data truly private in Python?" The correct answer is no — name mangling deters accidental access, it does not enforce real privacy the way private does in Java/C++.

V.7Function overloading

Unlike Java or C++, Python does not support true overloading — you cannot define the same method name twice with different parameter lists; the second definition simply replaces the first. The same flexibility is achieved instead with default arguments or *args/**kwargs.

class Calculator:
    def add(self, a, b=0, c=0):   # simulates overloading via default args
        return a + b + c

calc = Calculator()
print(calc.add(2, 3))       # 5
print(calc.add(2, 3, 4))    # 9 — same method name, variable arity

def add_all(*args):             # *args collects any number of positional arguments into a tuple
    return sum(args)

print(add_all(1, 2, 3, 4))   # 10
COMMON TRAPWriting two defs with the same name and different parameter counts is a classic exam "spot the error" question — Python keeps only the last definition; it does not raise an error, and it does not dispatch by argument count like Java does.

Unit V — last-night recap

  1. __init__ is the constructor; self is the current object, passed automatically.
  2. class Child(Parent): inherits everything; super().__init__() reuses the parent's constructor.
  3. Overriding = redefining an inherited method with the same signature in the subclass.
  4. Data hiding in Python is convention (_x) or name-mangling (__x) — never truly private.
  5. Python has no real function overloading; default arguments and *args/**kwargs substitute for it.
